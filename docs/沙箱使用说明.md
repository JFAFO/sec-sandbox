# 沙箱使用说明

> 适用代码：`sec_sandbox` 当前主线版本（2026-11-02）。
> 目标环境：Ubuntu 22.04 虚拟机；项目位于 Linux 原生目录（例如
> `~/Desktop/project`），不要在 `/mnt/d` 挂载盘上直接运行。
>
> 本文覆盖：TUI 的每个字段、所有可组合项、预设差异、启动后的可执行操作、
> 命令行网关、审计日志、手改 profile 以及常见问题。
> 课程现场演示请另见 [`沙箱运行指南.md`](沙箱运行指南.md)。

---

## 1. 一句话理解沙箱

`sec_sandbox` 是一个“命令执行安全网关 + OS 沙箱”的组合：

- **外层 bwrap**：把整个根目录设为只读，只开放工作区等少数可写路径；
  同时按读黑名单遮蔽 `~/.ssh`、`~/.aws`、`/etc/shadow` 等敏感位置。
- **cgroup**：限制内存、进程数与 CPU 配额。
- **命令层网关**：Agent 通过 `/bin/bash` 派生的命令先经过分类器——
  - 类 1：纯 bash utility 且命中白名单，经 AST 审计后放行；
  - 类 2：纯 Python 且通过静态审计，经运行时 `addaudithook` 放行；
  - 类 3：其余一切（混合命令、脚本、未知参数、解析失败）进入内层 bwrap。
- **内层 bwrap**：比外层更严，只有工作区可写，并遮蔽提权/挂载类可执行文件。

用户可见的结果只有三种：**放行**、**拦截并给出可读提示（退出码 126）**、
**内部错误（退出码 127）**。

## 2. 启动前的检查

在 VM 内部执行：

```bash
cd ~/Desktop/project

# 1. 项目自检：bwrap、嵌套 userns、cgroup 委托、seccomp 等
.venv/bin/python -m sec_sandbox --check

# 2. 安装环境自检（含 real-bash、venv、系统包）
bash scripts/setup.sh --check --project-dir "$PWD"

# 3. 确认真 bash 备份存在，且必须是普通文件
test -f /usr/bin/real-bash && echo "real-bash OK"
```

`/usr/bin/real-bash` 必须是 `cp` 出来的普通 ELF 文件，不能是符号链接：
目标 VM 的 bubblewrap 0.6.1 不支持把 `--ro-bind` 的目标设为符号链接。
缺失时重新执行：

```bash
sudo bash scripts/setup.sh --mode vm --project-dir "$PWD"
```

## 3. 启动方式总览

所有方式最终都会写入或读取
`~/.config/sandbox/profile.json`，再构建 bwrap/cgroup 并同进程 `exec`。

| 命令 | 是否显示 TUI | workspace 来源 | 适用场景 |
| --- | --- | --- | --- |
| `.venv/bin/python -m sec_sandbox` | ✅ | TUI 输入框，初始值为**当前目录** | 日常使用、现场改配置 |
| `.venv/bin/python -m sec_sandbox --preset strict` | ❌ | **当前工作目录** | 直接以严格预设启动 |
| `.venv/bin/python -m sec_sandbox --preset standard` | ❌ | **当前工作目录** | 演示与日常默认 |
| `.venv/bin/python -m sec_sandbox --preset loose` | ❌ | **当前工作目录** | 需要更多资源的开发 |
| `.venv/bin/python -m sec_sandbox --no-tui` | ❌ | **当前工作目录** | 仅开发调试，等同 standard |
| `.venv/bin/python -m sec_sandbox --profile PATH` | ❌ | profile 文件中的 `workspace` | 复用完整自定义配置 |
| `.venv/bin/python -m sec_sandbox --check` | ❌ | 不启动沙箱 | 只做自检 |

### 3.1 最重要的路径规则

**`--preset` 不使用预设里的 `$HOME/project`，而是把启动时的当前目录作为
workspace。** 例如：

```bash
cd ~/project
~/Desktop/project/.venv/bin/python -m sec_sandbox --preset standard
# 工作区 = ~/project

cd ~/Desktop/project
.venv/bin/python -m sec_sandbox --preset standard
# 工作区 = ~/Desktop/project（整个项目目录都可写）
```

因此演示时若要使用 `~/project` 里的假数据，必须先 `cd ~/project`，或者用
TUI 把工作区填成 `~/project`，或者使用一个 `workspace` 已写好的 profile。

### 3.2 参数互斥与优先级

- `--profile` 与 `--preset` 互斥，不能同时使用。
- `--check` 优先执行；即使同时给了 `--preset`，也只跑自检，不启动沙箱。
- `--no-tui` 会打印“仅开发使用”的警告，然后使用 standard 预设。
- TUI 模式下 `Esc` 或“取消”直接退出，不写 profile、不启动沙箱，退出码为 0。

## 4. TUI 界面与全部操作

### 4.1 界面结构

```text
✻ sec-sandbox
配置工作区与运行限制，然后进入沙箱
────────────────────────────────────────────────
工作区        [ /home/sandbox-dev/project            ]
内存上限      [ 512M                                 ]
最大进程数    [ 64                                   ]
CPU 配额      [ 50%                                  ]
权限          [ ] 允许网络    [ ] 允许脚本
预设          [严格]  [标准]  [宽松]
              [保存并启动]  [取消]

Ctrl+S 保存并启动    Esc 取消
```

界面使用深色背景、橙色强调，没有额外标题栏或状态栏；终端建议至少
`100×30`，窗口过小时可滚动。

### 4.2 TUI 中能做的每一个操作

| 操作 | 方式 | 结果 |
| --- | --- | --- |
| 切换焦点 | `Tab` / `Shift+Tab`，或鼠标点击 | 在输入框、复选框、按钮之间移动 |
| 修改工作区 | 在“工作区”输入框输入 | 保存时展开 `~`/`$HOME` 并规范化 |
| 修改内存上限 | 在“内存上限”输入框输入 | 保存时写入 profile |
| 修改最大进程数 | 在“最大进程数”输入框输入 | 必须为正整数，否则表单内报错 |
| 修改 CPU 配额 | 在“CPU 配额”输入框输入 | 保存时写入 profile |
| 允许网络 | 点击“允许网络”复选框或空格 | 写入 `network.enabled`（当前版本不改变运行时行为，见 §5.5） |
| 允许脚本 | 点击“允许脚本”复选框或空格 | 写入 `bash.allow_scripts`（当前版本不改变运行时行为，见 §5.6） |
| 保存并启动 | 点击“保存并启动”或按 `Ctrl+S` | 校验表单、写 profile、启动沙箱 |
| 取消 | 点击“取消”或按 `Esc` | 不写 profile、不启动沙箱，退出码 0 |
| 一键严格预设 | 点击“严格” | **立即**用严格预设 + TUI 打开时的工作区启动 |
| 一键标准预设 | 点击“标准” | **立即**用标准预设 + TUI 打开时的工作区启动 |
| 一键宽松预设 | 点击“宽松” | **立即**用宽松预设 + TUI 打开时的工作区启动 |

### 4.3 预设按钮的关键行为

点击预设按钮**不是把预设填进表单**，而是立即返回该预设并启动沙箱。
当前版本的行为是：

- 工作区取 **TUI 打开时**的初始值（通常是启动命令的当前目录），
  **不会**读取你在“工作区”输入框里刚改过的值；
- 内存上限、最大进程数、CPU 配额、允许网络、允许脚本的改动全部丢弃；
- 预设自带的资源值与开关生效；
- 随后写入 `~/.config/sandbox/profile.json` 并启动。

所以：

```text
想用预设默认值        → 先 cd 到目标工作区，再启动 TUI 并点“严格/标准/宽松”
想自定义工作区        → 在 TUI 填好后按 Ctrl+S（保存并启动）
想在 standard 基础上改 → 改完六项后按 Ctrl+S
想用 strict 的额外黑名单 + 自定义资源 → 手改 profile 后用 --profile
```

### 4.4 保存后发生什么

1. `_build_profile()` 读取六个控件；
2. 校验工作区格式与 `pids_max > 0`；
3. 写入 `~/.config/sandbox/profile.json`（0600，原子替换）；
4. 构建外层 bwrap 与 cgroup；
5. `exec` 进入沙箱交互 shell。

**TUI 每次打开都从 standard 预设 + 当前目录开始，不读取上一次保存的
profile。** 想复用上次配置时，请显式使用：

```bash
.venv/bin/python -m sec_sandbox --profile ~/.config/sandbox/profile.json
```

## 5. TUI 六个字段的取值与效果

### 5.1 工作区（workspace）

| 项 | 说明 |
| --- | --- |
| 格式 | 绝对路径，或以 `~` / `$HOME` 开头 |
| 是否必须存在 | 实际启动时必须存在且为目录；TUI 不做存在性检查，路径不存在会在启动阶段失败 |
| 规范化 | 保存时展开 `~`、`$HOME` 并解析为真实绝对路径 |
| 进入沙箱后的位置 | `--chdir` 到该目录 |
| 外层可写 | ✅ 该目录可写 |
| 内层可写 | ✅ 只有该目录可写 |
| 读权限 | 默认可读；若命中读黑名单模式会被遮蔽 |

示例：

```text
/home/sandbox-dev/project
~/project
$HOME/work/demo
```

不要填相对路径；不要填 `/`，否则等于把整个根目录作为可写工作区。

### 5.2 内存上限（memory_max）

| 项 | 说明 |
| --- | --- |
| 格式 | `<正整数>[K|M|G]`，建议带单位 |
| 默认值 | `512M` |
| 作用 | 传给 cgroup：`MemoryMax` / `memory.max` |
| 合法示例 | `256M`、`512M`、`1G`、`2G` |
| 不合法示例 | `512MB`、`0.5G`、`abc`、`0` |

不带单位时按字节理解，不建议这样填。超出内存限制的进程会被 cgroup
终止，而不是由 bwrap 处理（bwrap 没有资源参数）。

### 5.3 最大进程数（pids_max）

| 项 | 说明 |
| --- | --- |
| 格式 | 正整数 |
| 默认值 | `64` |
| 作用 | 传给 cgroup：`TasksMax` / `pids.max` |
| 用途 | 拦截 fork 炸弹、限制 Agent 及其子进程总数 |

运行真实 Agent 时 64 可能偏紧：Claude Code、mini 及其工具子进程都计入
同一 cgroup。若出现“无法创建进程/资源不足”，可提高到 `128` 或 `256`。

### 5.4 CPU 配额（cpu_quota）

| 项 | 说明 |
| --- | --- |
| 格式 | 百分比，`<整数或小数>%` |
| 默认值 | `50%` |
| 含义 | 相对于**一个 CPU 核**的配额；`200%` 表示最多使用 2 个核 |
| 合法示例 | `25%`、`50%`、`100%`、`200%`、`12.5%` |
| 不合法示例 | `0.5`、`50`、`-10%`、`0%` |

换算关系：`100%` 对应 cgroup 的 `100000 100000`，`50%` 对应
`50000 100000`。

> ⚠️ 目标 VM 的当前用户 session 可能没有向子 cgroup 委托 `cpu` 控制器，
> 此时 `cpu.max` 文件不存在，systemd 仍会记录 `CPUQuota` 配置但无法从
> cgroup 侧验证。可用下面的命令检查：
>
> ```bash
> cat /sys/fs/cgroup/cgroup.subtree_control
> # 当前 VM 只显示 memory pids；若不含 cpu，则 cpu.max 不可读
> ```
>
> `memory.max` 与 `pids.max` 不受影响，仍会按 profile 生效。

### 5.5 允许网络（network.enabled）

| 项 | 说明 |
| --- | --- |
| 默认值 | standard/loose 为 `true`，strict 也为 `true` |
| 写入位置 | `network.enabled` |
| 当前版本的实际效果 | ⚠️ **只写入 profile，不改变运行时行为** |

当前实现中：

- 取消勾选**不会**给 bwrap 添加 `--unshare-net`，沙箱仍然可以联网；
- 对 `curl`、`wget`、`git`、`pip`、`npm`、`ssh` 等识别到的网络命令，
  审查线始终启用，按 SSRF、安全域、数据源溯源等规则判定；
- 也就是说，这个复选框目前是“预留配置”，勾选与否行为一致。

如果演示中需要“完全断网”，当前版本不能通过 TUI 实现；应在设计上使用
`--unshare-net` 或外部网络策略，属于后续增强项。

### 5.6 允许脚本（bash.allow_scripts）

| 项 | 说明 |
| --- | --- |
| 默认值 | strict/standard 为 `false`，loose 为 `true` |
| 写入位置 | `bash.allow_scripts` |
| 当前版本的实际效果 | ⚠️ **只写入 profile，不改变路由行为** |

当前实现中：

- 脚本文件（`bash script.sh`）一律按类 3 降级到内层 bwrap；
- 普通命令仍按白名单判断是否走类 1；
- 勾选“允许脚本”不会把脚本提升为类 1/2，也不会放宽内层限制。

它是一个预留开关；演示时应说明“脚本默认降级”这一实际行为。

## 6. 三个预设的全部差异

预设是唯一的默认值来源。点击预设按钮或使用 `--preset` 时生效。

| 配置项 | `strict` | `standard` | `loose` |
| --- | --- | --- | --- |
| 工作区 | 当前目录 / TUI 输入 | 当前目录 / TUI 输入 | 当前目录 / TUI 输入 |
| 内存上限 | `256M` | `512M` | `2G` |
| 最大进程数 | `32` | `64` | `256` |
| CPU 配额 | `25%` | `50%` | `200%` |
| `allow_scripts` | `false` | `false` | `true` |
| `inner.max_depth` | `1` | `2` | `3` |
| 额外读黑名单 | `~/.gnupg`、`~/.kube`、`~/.password-store`、`~/.config/gcloud` | 无 | 无 |
| `network.enabled` | `true` | `true` | `true` |
| 其余字段 | 相同 | 相同 | 相同 |

补充说明：

- 三个预设都还会叠加代码内置的完整读黑名单：`~/.ssh`、`~/.aws`、
  `~/.config/gcloud`、`~/.kube`、`~/.gnupg`、`~/.password-store`、
  `~/.npmrc`、`~/.netrc`、`~/.git-credentials`、`/etc/shadow`、
  `/etc/sudoers` 等（完整列表见 `src/sec_sandbox/sandbox/mounts.py`）。
- `strict` 的“额外黑名单”是在此基础上再加四项，不是只遮蔽这四项。
- `inner.max_depth` 是类 3 内层沙箱允许的最大嵌套深度；超过即 Deny。

## 7. 所有可实现的组合

### 7.1 组合维度

TUI 可变的维度共六个：

```text
workspace × memory_max × pids_max × cpu_quota × network_enabled × allow_scripts
```

其中前四项在当前版本真实生效；后两项只写入 profile，不改变运行时行为
（见 §5.5、§5.6）。因此实际可观察到的有效组合是：

```text
workspace × memory_max × pids_max × cpu_quota
```

两个权限开关的四种组合如下（当前版本运行时等价，仅在 profile 中记录不同）：

| 允许网络 | 允许脚本 | profile 记录 | 当前实际效果 |
| --- | --- | --- | --- |
| 否 | 否 | `network.enabled=false`，`allow_scripts=false` | 网络审查仍启用；脚本仍类 3 |
| 是 | 否 | `true / false` | 同上（standard/strict 默认） |
| 否 | 是 | `false / true` | 同上 |
| 是 | 是 | `true / true` | 同上（loose 默认） |

预设按钮则提供三种固定组合。

### 7.2 预设组合（一键启动）

| 组合 | 资源 | 脚本开关 | 适用场景 |
| --- | --- | --- | --- |
| strict + 工作区 | 256M / 32 / 25% | 关 | 最小权限演示、资源紧张环境 |
| standard + 工作区 | 512M / 64 / 50% | 关 | 默认演示、日常使用 |
| loose + 工作区 | 2G / 256 / 200% | 开（仅记录） | 编译、安装依赖、真实 Agent 长任务 |

> 预设按钮使用 TUI 打开时的工作区；要指定其它目录，请先 `cd` 再启动，
> 或改用 `Ctrl+S`。

### 7.3 自定义组合（Ctrl+S）

`Ctrl+S` 始终以 **standard** 为基底，只覆盖表单六个字段。常用组合：

| 目标 | 工作区 | 内存 | 进程 | CPU | 说明 |
| --- | --- | --- | --- | --- | --- |
| 低资源演示 | `~/project` | `256M` | `32` | `25%` | 接近 strict 的资源，但没有 strict 的额外黑名单 |
| 标准 Agent | `~/project` | `512M` | `64` | `50%` | 默认值 |
| Agent 长任务 | `~/project` | `1G` | `128` | `100%` | Claude Code/mini 子进程较多时 |
| 编译/构建 | `~/project` | `2G` | `256` | `200%` | 接近 loose，但 `allow_scripts` 仍为 false |
| 单核限速 | 任意工作区 | `512M` | `64` | `100%` | 最多一个核 |
| 双核限速 | 任意工作区 | `1G` | `128` | `200%` | 最多两个核 |

注意：

- `Ctrl+S` 无法得到 strict 的额外读黑名单，也无法把 `inner.max_depth`
  改成 1；这些只能通过预设或手改 profile 获得。
- 当前版本无法通过表单得到“strict 资源 + 自定义网络/脚本”的组合；
  预设按钮会忽略其它未保存字段。
- 需要完整控制时，先启动一次生成 profile，再手改 JSON 并用 `--profile`
  启动（见 §10）。

### 7.4 操作组合

| 你想要的 | 正确操作 |
| --- | --- |
| 用预设默认值启动 | 点对应预设按钮 |
| 在 standard 基础上改资源 | 改字段 → `Ctrl+S` |
| 只看界面不启动 | `Esc` 或“取消” |
| 复用上次配置 | `--profile ~/.config/sandbox/profile.json` |
| 在指定目录启动 | 先 `cd` 到该目录，再用 `--preset`；或在 TUI 填工作区后按 `Ctrl+S`（不要点预设按钮） |
| 完全自定义读黑名单 / 安全域 / seccomp | 手改 profile + `--profile` |

## 8. 进入沙箱后可以做什么

启动成功后，你会看到一个新的交互式 shell。此时：

- 当前目录是 workspace；
- `/usr/bin/bash`（以及 `/bin/bash` 等 bash 路径）已被替换为 `safe-exec`
  网关；
- 真 bash 位于 `/usr/bin/real-bash`；
- `SECSAND_PROFILE`、`SECSAND_DEPTH`、`SECSAND_REAL_BASH` 已设置。

### 8.1 命令是否经过网关

| 操作 | 是否经过网关 | 说明 |
| --- | --- | --- |
| 在交互 shell 直接输入 `ls`、`cat` | ❌ | 由 real-bash 直接执行 |
| `bash -c '...'` | ✅ | 通过 `/bin/bash` 路径，进入网关 |
| `bash -lc '...'` / `bash -lc` + stdin | ✅ | 组合短选项已识别，保留登录 shell 语义 |
| `bash -c -l '...'` | ✅ | `-l` 按选项解析，后面的文本才是命令（Claude Code 兼容形式） |
| Agent 的 Bash 工具 | ✅ | 通常以 `bash -c` 形式调用 |
| `python3 -c '...'` | ✅ | 命中类 2 条件时走 Python 审计；否则类 3 |
| `sh -c '...'` | ❌ | `sh` 不是 bash 路径，网关不介入 |
| Agent 自带的文件读取工具 | ❌ | 不走网关，只受 bwrap 挂载视图约束 |

因此演示时要区分“命令层拦截”和“挂载视图兜底”：

```bash
# 挂载视图兜底：~/.ssh 已被 tmpfs 遮空，直接读不到
ls -la ~/.ssh
cat ~/.ssh/id_rsa

# 命令层拦截：经 bash 网关，返回 126 和可读提示
bash -c 'cat ~/.ssh/id_rsa'
echo "exit=$?"
```

### 8.2 常用验证操作

| 目的 | 命令 | 预期 |
| --- | --- | --- |
| 确认当前目录 | `pwd` | workspace |
| 确认可写工作区 | `echo hello > notes.txt && cat notes.txt` | 成功 |
| 确认根目录只读 | `touch /etc/secsand-demo` | 失败（只读文件系统） |
| 确认敏感目录被遮蔽 | `ls -la ~/.ssh` | 空目录或看不到真实内容 |
| 确认 `no_new_privs` | `grep NoNewPrivs /proc/self/status` | `NoNewPrivs: 1` |
| 查看 cgroup | `cat /proc/self/cgroup` | 指向当前 scope |
| 查看内存限额 | `cat /sys/fs/cgroup$(awk -F: '$1=="0"{print $3}' /proc/self/cgroup)/memory.max` | 与 profile 一致 |
| 查看进程限额 | 同上，把 `memory.max` 换成 `pids.max` | 与 profile 一致 |
| 触发命令层拦截 | `bash -c 'sudo ls'` | 提示 + `exit=126` |
| 触发类 3 降级 | `bash -c 'ls | grep x'` | 进入内层 bwrap 执行 |
| 启动 Claude Code | `~/.local/bin/claude` | Agent 正常启动 |
| 启动 mini | `~/.local/bin/mini -t "..."` | Agent 正常执行 |
| 退出沙箱 | `exit` | 回到宿主 shell |

### 8.3 文件视图与写权限

| 路径 | 外层 | 内层（类 3） |
| --- | --- | --- |
| `/` | 只读 | 只读 |
| workspace | 可写 | 可写 |
| `~/.claude` | 可写（存在时） | 只读 |
| `~/.claude.json` | 可写（存在时） | 只读 |
| `~/.local/state/sec-sandbox` | 可写 | 只读（工作区之外不可写） |
| `/tmp` | tmpfs，可写 | tmpfs，可写 |
| 读黑名单中的路径 | 遮蔽 | 遮蔽，额外遮 `~/.config`、`~/.gitconfig` |

### 8.4 审计日志

默认位置：

```text
~/.local/state/sec-sandbox/audit.jsonl
```

每条 JSON 记录包含：

| 字段 | 含义 |
| --- | --- |
| `ts` | 本地时间（ISO 8601） |
| `source` | 事件来源，通常为 `gateway` |
| `pid` | 进程号 |
| `depth` | 网关嵌套深度 |
| `mode` | 调用形态：`command_string` / `script` / `stdin` / `interactive` / `unknown` |
| `class` | `bash_utility` / `python_script` / `sandboxed` |
| `decision` | `allow` / `deny` / `downgrade` |
| `reason` | 内部原因码（用户界面不显示） |
| `rule_ids` | 命中的规则编号 |
| `network` | 网络判定详情 |
| `command_sha256` | 命令文本哈希 |
| `command_preview` | 命令预览；默认关闭，仅在 `log_command_text=true` 时写入并脱敏 |
| `exit_code` / `signal` | 执行结果 |
| `duration_ms` | 耗时 |
| `profile_hash` | profile 文件哈希 |
| `error` | 内部错误类型（如有） |

常用查询：

```bash
# 最近 20 条的关键字段
tail -n 20 ~/.local/state/sec-sandbox/audit.jsonl \
  | jq -c '{ts,decision,reason,class,exit_code}'

# 统计放行/拦截数量
jq -r '.decision' ~/.local/state/sec-sandbox/audit.jsonl | sort | uniq -c

# 只看网络拦截
jq -c 'select(.network.decision == "deny")' \
  ~/.local/state/sec-sandbox/audit.jsonl
```

## 9. 命令行网关模式（不启动沙箱）

适合单独验证某条命令的拦截结果，也适合课程演示。

```bash
cd ~/Desktop/project

SECSAND_PROFILE="$HOME/.config/sandbox/profile.json" \
  .venv/bin/python bin/safe-exec -c 'ls'
```

常用示例：

```bash
# 正常命令：放行，退出码 0
SECSAND_PROFILE="$HOME/.config/sandbox/profile.json" \
  .venv/bin/python bin/safe-exec -c 'ls'

# 敏感路径：拦截，退出码 126
SECSAND_PROFILE="$HOME/.config/sandbox/profile.json" \
  .venv/bin/python bin/safe-exec -c 'cat ~/.ssh/id_rsa'

# 高危命令：拦截
SECSAND_PROFILE="$HOME/.config/sandbox/profile.json" \
  .venv/bin/python bin/safe-exec -c 'sudo ls'

# 复合命令：类 3 降级到内层 bwrap
SECSAND_PROFILE="$HOME/.config/sandbox/profile.json" \
  .venv/bin/python bin/safe-exec -c 'ls | grep x'
```

退出码约定：

| 退出码 | 含义 |
| --- | --- |
| `0` | 放行并成功执行 |
| `126` | 被策略拦截 |
| `127` | 内部错误（profile、沙箱构建、审计等异常） |
| 其他 | 被执行命令自身的退出码 |

> 说明：`python -m sec_sandbox.gateway.cli` 目前没有 `__main__` 入口，
> 直接运行不会有输出；请使用上面的 `bin/safe-exec` 形式。

课程演示脚本必须在**沙箱内部**运行，逐条打印命令、输出与判定：

```bash
# 先在 ~/project 启动 sandbox，进入沙箱 shell 后：
~/Desktop/project/.venv/bin/python \
  ~/Desktop/project/scripts/demo_attacks.py --pause
```

脚本共 12 步，覆盖工作区、只读根、SSH 遮蔽、命令层拦截、SSRF、
数据外发、`no_new_privs` 与 cgroup。直接命令用 `/usr/bin/real-bash`
模拟交互 shell，网关命令用 `/usr/bin/bash` 进入 `safe-exec`；
它不会自动启动沙箱，在沙箱外运行会直接报错退出。

## 10. 手改 profile（TUI 之外的配置）

TUI 只暴露六个字段。读黑名单、安全域、seccomp 拒绝列表、审计轮转等需要
直接编辑：

```text
~/.config/sandbox/profile.json
```

编辑后用完整路径启动：

```bash
.venv/bin/python -m sec_sandbox --profile ~/.config/sandbox/profile.json
```

### 10.1 可以手改的常用字段

| 字段 | 作用 |
| --- | --- |
| `filesystem.read_blacklist` | 追加读遮蔽路径，动作 `mask` / `devnull` / `ro_bind` |
| `filesystem.write_whitelist` | 额外写白名单；只能位于 workspace 或运行必需目录 |
| `network.safe_domains` | 允许直接放行的域名 |
| `network.llm_judge` | 规则无法定论时的 LLM 兜底（默认关闭；超时即 Deny） |
| `inner.masked_executables` | 内层遮蔽的可执行文件（默认含 sudo/mount 等） |
| `inner.seccomp_denylist` | 内层 seccomp 拒绝的 syscall |
| `audit.log_command_text` | 是否记录脱敏后的命令预览 |
| `audit.max_bytes` / `backups` | 审计日志轮转 |

### 10.2 安全约束

- `workspace` 必须是绝对路径或 `~`/`$HOME` 前缀；
- 路径不得包含 `..`；
- `filesystem.write_whitelist` 只能写 workspace 子路径或
  `~/.claude`、`~/.claude.json`、审计目录；
- `audit.log_dir` 必须位于 `$HOME/.local/state` 下；
- `schema_version` 必须为 `1`；
- profile 校验失败时启动返回 127，不会带着半截配置进沙箱。

## 12. 常见问题

| 现象 | 原因与处理 |
| --- | --- |
| 运行 `sandbox` 没有 TUI | 使用了 `--preset` / `--no-tui` / `--profile`；去掉这些参数才会显示 TUI |
| 工作区不是 `~/project` | `--preset` 用当前目录作为 workspace；先 `cd ~/project`，或用 TUI/`--profile` |
| `touch ~/notes.txt` 失败 | 家目录除 `~/.claude` 等少数路径外都是只读；请写入 workspace |
| `cat ~/.ssh/id_rsa` 输出为空 | 外层 bwrap 已用 tmpfs 遮蔽，这是正常的 |
| `bash -c 'cat ~/.ssh/id_rsa'` 返回 126 | 命令层敏感路径拦截，属于预期 |
| `bash -c 'sudo ls'` 返回 126 | 高危命令拦截，属于预期 |
| Agent 起不来或进程数不足 | 提高 `pids_max`（如 128/256）与内存上限 |
| `real-bash` 不存在 | 重新执行 `setup.sh`；不要用 `ln -s`，必须是普通文件 |
| 启动报 `ModuleNotFoundError` | 确认通过项目 `.venv/bin/python` 启动，且已同步最新代码 |
| 审计日志为空 | 检查 profile 的 `audit.log_dir` 是否为 `~/.local/state/sec-sandbox` |
| 取消勾选“允许网络”仍能联网 | 当前版本该开关只写 profile，不改变运行时行为 |
| 勾选“允许脚本”脚本仍被降级 | 当前版本该开关只写 profile，脚本一律类 3 |
| cgroup 中找不到 `cpu.max` | 用户 session 未委托 `cpu` 控制器；`memory.max`/`pids.max` 仍生效 |
| 同时开两个 sandbox 后行为异常 | profile 是全局单一文件，后启动的会覆盖先启动的；一次只保留一个 sandbox |
| 沙箱内 `python getcwd()` 指向 `~/.local/share/Trash/...` | 工作区目录曾被移动/重建，旧会话持有旧 inode；`exit` 后在新的 `~/project` 重新启动 sandbox |
| TUI 显示不全 | 终端至少 100×30；或改用 `--preset` / `--profile` |
